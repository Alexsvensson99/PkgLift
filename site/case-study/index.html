PkgLift/Case study
Pinned real-project evidence

A partial migration that still builds

The strongest test of conservative migration is not moving everything. It is moving exactly what is proven safe, preserving the rest, and verifying the result.

Project: Amazon IVS Grid Feed for iOS sample, pinned at commit 5573a57d4cb7e10f7ad86f95c548ddfbeabc6e1d. The upstream sample reports an MIT-0 license.

Starting dependency state

DependencyPinned versionReviewed outcome
SDWebImage5.18.1AUTO Migrate to its verified SwiftPM package/product.
AmazonIVSPlayer1.40.0NON-AUTO Preserve under CocoaPods.

The controlled workflow

Two isolated checkouts

The baseline and migration paths could not contaminate one another.

Baseline established

pod install --clean-install retained the pinned direct versions, and the iOS Simulator build passed.

Dry run proven clean

Analysis, planning, and migration preview left tracked files, the index, and visible untracked files unchanged.

Complete AUTO set checked

The harness required the entire automatic set to equal only SDWebImage before mutation.

Partial migration applied

PkgLift removed the SDWebImage pod declaration and added exact SwiftPM linkage. CocoaPods then refreshed the dependency that remained.

Structure, resolution, and build verified

The migrated workspace resolved SwiftPM and built successfully using the validated workspace scheme.

The pilot found a real defect

The first full run exposed that package resolution for a selected workspace did not receive the already validated scheme when an explicit derived-data path was used. The later build had the scheme and succeeded, making the missing argument reproducible and focused.

The defect became a dedicated issue and regression tests, was fixed, and the complete pilot then passed. This is the intended value of real-project evidence: it turns an integration failure into a small, testable product correction.

Final safety result

  • Only the reviewed SDWebImage migration was applied.
  • AmazonIVSPlayer remained at version 1.40.0 under CocoaPods.
  • SwiftPM package resolution and the final simulator build passed.
  • No application source or resource file was changed.
  • No repository secret or upstream write credential was available to the workflow.
